# Reports

dicomqc v0.2 writes standalone HTML, JSON, CSV, and MultiQC custom-content reports.

```bash
dicomqc scan study/ --html report.html --json report.json --csv findings.csv --multiqc
```

## Redaction

Reports omit raw DICOM tag values. Findings and the tag list
show whether a value is absent, empty, or present, but not the observed value.

File paths and other report details may still identify people or datasets.
Review reports before sharing them.

## HTML

Create a report you can open directly in a browser:

```bash
dicomqc scan study/ --html report.html
dicomqc compare raw/ candidate/ --manifest pairs.csv --html comparison.html
```

Each HTML file includes its styles and scripts. It works offline without
MultiQC, a web server, or additional Python packages. The report shows audit
counts, findings, and recommended fixes. Comparison reports also show file and
pair coverage using manifest references.

Start with the verdict and issue groups. Charts, coverage, and audit metadata
are folded into **Charts and audit details** (including pairing coverage for
comparisons). **Search and filter** opens the optional review controls. These
panels start closed to keep recommended actions prominent. Empty and unreadable
inputs are explicitly distinguished from a passing audit.

Findings are grouped by rule, severity, message, recommended action, and standards
references. Each issue shows the shared action once, with its finding count and
distinct file/pair-reference count. Expand **View affected files / pairs** to see
every occurrence, field, and value state. Repeated fields are retained, so one
reference can have multiple findings. Groups are ordered by severity: errors,
warnings, then information. On narrow screens the workspace stacks vertically,
and expanded occurrences use labeled rows instead of a wide table.

Category bars summarize findings across all severities, not unique files.
Comparison reports also chart manifest pairs: both files readable, a file missing,
or a file unreadable. A pair with both a missing and an unreadable file is counted
as missing; unpaired files are excluded from this chart. Readable pairs can still
have findings. Each bar includes an exact count, and charts work without JavaScript.
Charts summarize the full audit and do not change when you filter the issues.
Click a category bar to filter the findings; click it again to clear that category.
The Category menu shows the active selection. Category, severity, and search
filters combine, and **Reset filters** clears all three.

Search by file, rule, field, or recommendation, and filter findings by severity.
Search matches shared issue text and individual file/field occurrences. Matching
file lists open automatically; the counter distinguishes groups from findings.
Without JavaScript, all groups remain visible and their file lists can be expanded.
The print button includes all
findings, even when filters are active. No raw DICOM records or tag values are
embedded in the HTML. Unreadable files are listed with a generic message rather
than parser details.
Rule IDs and standards references appear inside each issue's expandable file list.
Use **Expand file lists** to open the visible groups together. **Reset filters**
also collapses file lists. Printing includes every group and occurrence, even
when a group is collapsed or hidden by a filter. Folded charts and audit details
are also included in print. **Print report** is
available at the top, including for reports with no findings. The browser's own
print command also works without JavaScript.

Both demos create HTML reports automatically:

- `dicomqc demo`: `dicomqc-demo/dicomqc/report.html`
- `dicomqc demo --compare`: `dicomqc-demo/before.html` and
  `dicomqc-demo/after.html`

Reports generated by a demo are labeled as synthetic data. To use a different
directory, pass `--output-dir DIR`.
Comparison demo reports link to each other with **Before corrections** and
**After corrections**. Keep both HTML files in the same folder to use these links.

## JSON

The JSON report includes:

- tool metadata
- selected profile
- summary counts
- scanned files and their metadata
- findings
- skipped files

## CSV

The CSV report contains one row per finding with:

- path
- rule ID
- profile ID
- severity
- tag and keyword
- value state
- message
- recommendation

## MultiQC

`--multiqc` writes a `dicomqc_mqc/` directory by default:

```bash
dicomqc scan study/ --multiqc
multiqc .
```

The directory contains small `*_mqc.yaml` custom-content files. MultiQC renders
these as dicomqc general statistics, a compact audit-status table, and a
findings table without raw tag values. Keep the JSON and CSV files as the audit
records. Use MultiQC to view the results alongside other QC reports.

Use a custom output directory when needed:

```bash
dicomqc scan study/ --multiqc reports/dicomqc_mqc
```

## Example Report

The CLI includes a reproducible demo that generates synthetic DICOM files and
writes dicomqc reports without raw tag values:

```bash
dicomqc demo --output-dir dicomqc-demo --force
```

If MultiQC is installed, render the custom-content bundle:

```bash
multiqc dicomqc-demo/dicomqc --outdir dicomqc-demo --force --config examples/multiqc/multiqc_config.yaml
```

The rendered report is written to:

```text
dicomqc-demo/multiqc_report.html
```
